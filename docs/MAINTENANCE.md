# 瞎分享导航 · 项目维护说明(内部文档)

> 这份文档是写给**你自己**看的维护手册,记录了这个项目的技术决策和
> 日常维护方法。给别人看的项目介绍在 `README.md` 里。

这份代码是从一个旧的 WordPress + 导航 CMS 站点重构而来的静态版本,现在
挂在子域名 **`nav.xiafenxiang.com`** 下面:不再用 WordPress + 导航 CMS,
改成纯粹的 HTML + CSS + JS 静态站点,没有任何后端、数据库、构建工具,
双击 `index.html` 或者随便丢到一个静态托管上就能跑。

**你本地保存这份代码的那个文件夹就是这个项目的根目录**,所有维护都在
这个文件夹里进行(文件夹叫什么名字都可以,不影响线上域名)。

---

## 一、为什么不用开源 CMS,直接手写前端?

这是最早的问题,结论还是没变,记一下原因方便以后回忆:

- 这个站本质上就是"一堆分类 + 一堆链接卡片",没有评论、没有用户系统、
  没有后台管理需求(维护者只有你自己,直接改一个 JS 文件里的数据就行)。
- 开源导航类 CMS(比如各种 PHP/Node 导航系统)对于这个体量来说太重:
  需要数据库、需要服务器环境、需要单独的后台账号密码、升级还要担心兼容性。
- 纯静态站点几乎没有攻击面、没有服务器成本(或者成本极低),访问速度也
  更快,SEO 友好(内容直接在 HTML 里,不需要等接口返回)。
- 唯一的"代价"是没有可视化后台——但对于一个人维护、更新频率不高的
  导航站来说,直接改一个格式良好、注释清楚的 JS 文件,比学一个陌生 CMS
  后台的操作逻辑更快。

所以结论没变:**继续纯前端,不引入任何 CMS / 数据库 / 构建工具**。

## 三、为什么把"每个网站一个独立详情页"去掉了

这是那一轮改动里最大的一个决定,详细说一下权衡过程,方便你以后如果
后悔了也知道怎么权衡回去。

**之前的做法**:每一条网站链接,除了在首页显示一张卡片,还会额外生成一个
独立的 HTML 详情页(`go/xxx.html`),里面单独放这个网站的名字、简介、
一个大大的"前往访问"按钮。目的是让搜索引擎能收录很多个"长尾页面"
(比如别人搜"网站名 + 简介关键词"也可能搜到你),对 SEO 有一点点帮助。

**代价**:这个方案让"加一个新网站"从"改一行 JSON"变成了"改
`data.js` + 重新运行 Python 生成脚本 + 生成/覆盖一个新的 `go/*.html`
文件",维护链路变长了,而且 `go/` 目录下积累了 160 个高度雷同、
内容很薄的页面。

**关键信息**,让这个权衡的天平彻底倒向"去掉":

1. 明确"如果太麻烦,不要详情页了",维护成本已经超过了它带来的好处。
2. 不再买/续费独立域名,而是挂在子域名 `nav.xiafenxiang.com` 下面。
   子域名相比独立域名,在搜索引擎眼里"域名权重"通常更低、更慢积累
   信任度,而且这类"导航站 + 大量近似详情页"的页面,本身被搜索引擎
   判定为"低质量聚合页"的风险也不低。在这种起点本来就不高的域名上,
   硬堆 160 个内容单薄的详情页,带来的边际 SEO 收益非常有限,远远
   抵不过它增加的维护复杂度。

**结论**:详情页对这类个人导航站的 SEO 帮助本来就很有限,去掉是划算的。
去掉之后:

- **加一个新网站,现在只需要改 `assets/js/data.js` 这一个文件**,不需要
  碰任何其它文件,也不需要跑任何脚本。
- 首页的每张网站卡片,点击后直接跳转到那个网站本身(不再有"详情"按钮
  和中间页)。
- 如果以后流量做起来了、确实想要更细的 SEO 布局,这个方向随时可以
  重新加回来(比如只给"精选/重点推荐"的一小部分网站单独做详情页,
  而不是全站都做)。

## 四、日常维护:怎么加/删/改一个网站

**只需要编辑一个文件:`assets/js/data.js`。**

打开这个文件,你会看到最上面是一大段说明注释,下面是:

```js
window.NAV_DATA = {
  "categories": [
    {
      "id": "changyong",          // 分类的英文标识,不显示在页面上,尽量别改
      "name": "常用网站",          // 分类显示的中文名
      "subgroups": ["常用软件", "软件资源"],  // 这个分类下面的子分类 tab(没有就写 [] 或者只写一个)
      "links": [
        {
          "name": "淘宝网",
          "url": "https://www.taobao.com/",
          "desc": "国内领先的网购平台",
          "group": "常用软件"        // 属于上面 subgroups 里的哪一个 tab
        }
      ]
    }
  ]
};
```

### 加一个新网站

在对应分类的 `links` 数组里,新增一个对象:

```js
{
  "name": "网站名称",
  "url": "https://example.com/",
  "desc": "一句话简介,建议不超过 30 个字",
  "group": "对应的子分类名(要跟 subgroups 里的某一项完全一致)"
}
```

保存文件,刷新首页就能看到,**不需要改任何其它文件,不需要跑任何脚本**。

### 删除一个网站

找到对应的对象,整段删掉(注意别落下前面/后面多余的逗号)即可。

### 调整顺序

`links` 数组里对象的先后顺序,就是网站卡片在页面上的先后顺序,直接
剪切、粘贴调整位置就行。分类(`categories`)之间的顺序同理。

### 新增一个分类,或者新增一个子分类 tab

- 新增分类:在 `categories` 数组里加一个新对象,写好 `id`/`name`/
  `subgroups`/`links`。
- 新增子分类 tab:在对应分类的 `subgroups` 数组里加一个新的子分类名字,
  然后把属于它的网站的 `group` 字段填成这个名字。如果一个新 tab 暂时
  还没有网站,页面上会自动显示"该子分类内容建设中"的占位提示,不会
  报错。

改完 `data.js` 之后,直接用浏览器打开 `index.html` 看看效果就行,
不需要任何"编译/构建"步骤。

> **关于"瞎分享"友情链接/软件资源两条记录**:`data.js` 里有两条指向
> `https://xiafenxiang.com/` 的记录(一条在"软件工具"分类下,一条在
> "友情链接"分类下)。现在这个导航站本身挂在 `xiafenxiang.com` 的子域名
> 下,但这两条链接指向的是原本就存在的另一个独立网站/资源分享圈子,
> 跟这个导航项目是两回事,已确认**保留不动**,不需要因为域名关系而删除
> 或修改。

## 五、榜单页维护:`assets/js/rankings-data.js`

`rankings.html` 用的是单独的数据文件 `assets/js/rankings-data.js`,跟
首页 `data.js` 是同一个思路——纯 JSON,改这一个文件就能更新榜单,不需要
碰任何 HTML/JS。

原网站的榜单是"根据实际访问量自动统计、实时刷新"的,但这一版是纯静态
站点,没有后端来统计点击量,所以做不到真正的自动统计,改成了"你自己
维护的静态榜单"。三个榜(日榜/周榜/月榜)结构完全一样,每一项:

```js
{ "name": "网站名称", "url": "https://example.com/", "desc": "一句话简介" }
```

加/删/调整排名:跟首页 `data.js` 一样,直接在对应数组里增删/剪切粘贴
顺序,顺序就是排名(第一个是第 1 名)。图标用的是跟首页完全同一套
"本地图标优先、自动抓取兜底"的逻辑,不需要额外配置。

## 六、顶部标语维护:`assets/js/slogans.js`

顶部搜索框左边那句标语(比如"人生而自由,却往往不在枷锁中。"),是从
`assets/js/slogans.js` 里维护的一个数组中**随机**挑一句显示的,每次打开
页面(含刷新)都可能换一句,5 个页面共用同一份逻辑
(见 `assets/js/app.js` 里的 `initTopbarSlogan`)。

怎么加/删/改一句标语:直接在 `slogans.js` 的数组里增删一个字符串就行,
跟 `data.js` 的编辑方式一样,不需要碰任何 HTML 或其它 JS 文件,保存后
刷新页面即可看到效果(因为是随机挑选,可能要刷新几次才会看到新加的
那一句,这是正常的)。数组里如果只留一句,效果就跟"写死"一样,每次都
显示同一句。

## 七、网站图标(favicon)是怎么显示的

这一版的图标逻辑是"你可以随时手动接管"的模式,一共 4 级优先级,
按顺序尝试,前一级失败才会用下一级,**普通情况下你什么都不用管**:

1. **`assets/icons/` 文件夹里的本地图片**(优先级最高,你手动放的)
2. 网站自己域名下的 `/favicon.ico`(自动抓取)
3. 一个免费的第三方图标接口兜底(自动抓取)
4. 都失败 → 显示"网站名首字母"的纯色小图标,不会裂图

> 这里说的是**每个导航卡片**的小图标,跟站点本身的浏览器标签页图标
> (`assets/img/favicon.png`)是两回事——后者已经是本地文件,不需要
> 再手动维护。

### 什么时候需要你手动放图标

自动抓取(第 2、3 级)大部分时候够用,但总有一些网站的图标本身很丑、
模糊、或者是纯文字 logo,放在统一风格的卡片里显得不协调、不统一。
这种情况下,不需要改任何代码,只要:

1. 打开 `assets/icons/icon-filenames-reference.txt`,搜网站名称或网址,
   找到"应该存成的文件名"(规则是:域名去掉 `www.`、把 `.` 换成 `-`、
   后缀 `.png`,比如 `taobao.com` → `taobao-com.png`)。
2. 找一张你觉得好看的图片,存成这个文件名,放进 `assets/icons/`
   文件夹里。
3. 刷新首页,这个网站的图标就会自动换成你放的这张图(因为它现在是
   优先级最高的第 1 级了)。

详细说明和图片要求(格式、尺寸)见 `assets/icons/README.md`。

> 注意:这边没办法直接帮你批量下载真实的网站 logo 图片(运行环境
> 没有可以下载图片文件的网络权限),所以 `assets/icons/` 目前是空的,
> 需要你自己陆续把觉得丑的那些图标换掉。不着急,不换的网站会自动走
> 第 2/3 级兜底,不会有任何问题,只是好看程度差一点。

## 八、logo / favicon / 二维码这一轮是怎么处理的

这一轮把整个站从旧品牌改名成了"瞎分享导航 / nav.xiafenxiang.com"
(旧域名不再续费),顺带处理了几个遗留的"临时方案":

- **Logo**:原来的 logo 图片文件本身是旧站的历史遗留图,图片像素里
  直接画着旧品牌的文字和旧域名,换了新域名后没法再直接拿来接着用
  (不是简单换个文件名/换个 host 就能解决,图片内容本身就是旧品牌)。
  所以这一轮**去掉了 `<img>` 图片 logo**,改成了页面自带的那一套纯
  CSS 画的徽标(圆角渐变方块 + "享"字 + "瞎分享导航"文字),一直是
  永久显示状态,不再依赖任何外部图片,不会有裂图/404 风险。以后如果
  你设计了一个正式的图片 logo,在 `assets/css/style.css` 里
  `.site-logo` 相关的样式里加回一个 `<img>` 标签、把现在这个纯 CSS
  版本改成 `onerror` 兜底就行,标记见样式表里的注释。
- **favicon(浏览器标签页图标)**:原来的也是旧站的红色圆底字母图标,
  同样带着旧品牌,不适合直接沿用。现在用本地生成的一枚图标替代:
  跟 logo 同一套渐变配色(`--color-primary` → `#7b9bff`),白色"享"字,
  文件在 `assets/img/favicon.png`(标准图标)和 `favicon-180.png`
  (iOS 主屏图标)。想换成你自己设计的图标,直接覆盖这两个文件即可,
  不需要改 HTML。
- **微信 / Telegram 二维码**:这两张是你的真实联系方式,不是品牌相关的
  图,所以直接把原来在线的两张图保存成本地文件:
  `assets/img/wechat-qr.png`、`assets/img/telegram-qr.png`,全站所有
  引用这两张图的地方(页脚气泡、页脚二维码区、右下角悬浮按钮气泡)
  都已经换成本地路径,不再依赖旧站那边的图片链接。

## 十、其它小说明

- **搜索**:首页支持站内搜索,也可以切换到百度/Google/必应/淘宝搜索。
  在占位页(如 about.html)上搜索,会自动跳转回首页并接着帮你把搜索
  结果显示出来。
- **深色模式**:右上角有主题切换按钮,选择会记在浏览器本地
  (localStorage),下次打开自动记住。
- **移动端**:侧边分类栏在窄屏下会变成顶部换行的一排标签;页脚在手机
  上是单列堆叠布局,这些都已经在 `style.css` 里用响应式断点
  (860px / 520px)处理好了,不需要额外维护。
- **不需要任何构建工具**:没有 npm/webpack/打包这些东西,`index.html`
  直接用 `<script>` 标签引入 `data.js`、`slogans.js`、`app.js`,改完
  文件刷新浏览器就是最终效果。
